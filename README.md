# Elevate Arabia website

A minimal, fast, static website for [elevatearabia.com](https://www.elevatearabia.com/).
It is plain HTML, CSS and a little JavaScript, generated by one standard-library Python
script and deployed to GitHub Pages by GitHub Actions. There are no frameworks, no
external fonts, nothing to install, and every page works without JavaScript.

What was wrong with the original prototype, and what changed: [`docs/REVIEW.md`](docs/REVIEW.md).

## Run it locally

Requires Python 3.9 or newer.

```bash
python3 build.py --serve
```

Open http://localhost:8000. Rebuild after each edit with `python3 build.py`.

## Edit

| What | Where |
|---|---|
| Copy: services, sectors, team, contact details, social links, client logos | `content.py` |
| Logos, team photos, brand files | `assets/images/` (WebP; drop in a file and reference its slug) |
| Page templates and layout | `build.py` |
| Styles and design tokens | `assets/css/styles.css` |
| Mobile menu and contact form | `assets/js/app.js` |

In headlines, text inside `[square brackets]` renders in the lighter second tone.

Every build checks all internal links, `#anchors`, duplicate ids and one `<h1>` per page,
and fails if anything is broken. CI runs the same checks on every pull request.

## Deploy to GitHub Pages

1. In the repo, open **Settings → Pages → Build and deployment** and set **Source** to **GitHub Actions** (one time).
2. Merge to `main`. The workflow `.github/workflows/pages.yml` builds the site and publishes it at
   `https://<owner>.github.io/<repo>/`. You can also run it manually from the **Actions** tab.

Pull requests run the build and link checks only, without deploying.

The site is **noindex by default**, so a preview deploy never competes with the live site in search.

### Going live on elevatearabia.com

1. Settings → Pages → **Custom domain**: `www.elevatearabia.com`. Add the DNS record GitHub shows you
   (a `CNAME` for `www` pointing to `<owner>.github.io`), then tick **Enforce HTTPS**.
2. Settings → Secrets and variables → Actions → **Variables**: add `INDEXABLE` = `true`.
3. Re-run the workflow. Canonical URLs and `sitemap.xml` pick up the custom domain automatically.

Before switching the domain, work through the sign-off list in [`docs/REVIEW.md` §5](docs/REVIEW.md#5-confirm-before-this-replaces-the-live-domain).
Above all, migrate the Privacy Policy and Terms text, because those pages currently link to the existing site.

## Browser QA (optional)

Checks every page at 6 widths for overflow, JS errors and WCAG AA text contrast. It also
tests the mobile menu, anchor offsets under the sticky header, contact form validation, the
mailto output and the 404 page.

```bash
npm install --no-save playwright && npx playwright install chromium
```

```bash
python3 build.py && node scripts/qa.cjs --shots
```

Screenshots are written to `qa-output/`, which git ignores.

## Design

| Token | Value | Use |
|---|---|---|
| `--ink` | `#142536` | Headings, primary buttons |
| `--text` | `#2c3b49` | Body copy |
| `--muted` | `#5a6977` | Secondary copy (5.6:1) |
| `--tone` | `#7a8793` | Second tone in large headlines only |
| `--accent` | `#c00200` | Brand red (sampled from the logo): buttons, numbers, markers, focus ring |
| `--line` | `#e3e7ea` | Hairline dividers |
| `--soft` | `#f5f7f8` | Panels, footer |

The layout uses a 1120px max width and two-column sections (heading left, content right),
stacking to one column below 900px. Red is used sparingly: primary buttons, numbering and small markers.

## Contact form

The form validates in the browser, then opens a pre-filled email to `SITE.enquiry_email` in the
visitor's mail app. Nothing is sent to or stored by the website, which keeps it fully static.
To accept submissions directly, point the form at a form backend and update the Privacy Policy.
