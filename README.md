# Elevate Arabia website

A minimal, fast, static website for [elevatearabia.com](https://www.elevatearabia.com/).
It is plain HTML, CSS and a little JavaScript, generated by one standard-library Python
script and deployed to GitHub Pages by GitHub Actions. There are no frameworks, no
third-party requests (the font is self-hosted), nothing to install, and every page works
without JavaScript.

- English at `/`, Arabic at `/ar/`, Chinese at `/zh/`, Japanese at `/ja/`.
- What was wrong with the original prototype, and what changed: [`docs/REVIEW.md`](docs/REVIEW.md).
- Status of each finding in the Flopexa website review (28 October 2026): [`docs/review-status.md`](docs/review-status.md).

## Languages

| Language | Address | Content file | Font |
|---|---|---|---|
| English | `/` | `content.py` | IBM Plex Sans (self-hosted) |
| Arabic | `/ar/` | `content_ar.py` | Readex Pro (self-hosted), right-to-left |
| Chinese (Simplified, Mandarin) | `/zh/` | `content_zh.py` | The visitor's system font (PingFang SC, Microsoft YaHei, Noto Sans SC) |
| Japanese | `/ja/` | `content_ja.py` | The visitor's system font (Hiragino, Yu Gothic, Noto Sans JP) |

All four come from the same templates. Every page has a language menu (a globe in the header,
which on phones stays visible next to the menu button), and the footer lists all four. Each
link goes to the same page in that language, and `hreflang` tags tell search engines how the
versions relate.

- English copy, including the interface text in `UI`, is in `content.py`.
- Each translation file supplies only the text, matched by slug or name. Structure (slugs,
  links, photos, phone numbers, logos) comes from `content.py` through `translation.py`.
- If you add a service, sector, team member or `UI` string in English, add it to every
  translation. The build stops with an error that names the language and what is missing.
- Chinese and Japanese use system fonts because Chinese and Japanese web fonts are several MB.
  Every current phone and computer has a good one, and each language lists its own fonts so
  characters get the right regional shapes. Japanese headings break at natural phrase
  boundaries, and Chinese headings break at punctuation on wide screens.
- To add another language, copy `content_ja.py`, translate it, give it a new `LANG` (code,
  folder, name), and add it to `LANGS` in `build.py`.

All three translations need a native-speaker review before launch. People's names stay in
Latin script, as on the live site.

## Run it locally

Requires Python 3.9 or newer.

```bash
python3 build.py --serve
```

Open http://localhost:8000. Rebuild after each edit with `python3 build.py`.

In headlines, text inside `[square brackets]` renders in the lighter second tone.

Every build checks all internal links, `#anchors`, duplicate ids, one `<h1>` per page,
empty headings and invisible characters, and fails if anything is wrong. CI runs the same
checks on every pull request.

Switches in `content.py`:

- `SHOW_PARTNER_CLIENTS`: the 12 global logos from the live site appear to be the partner's
  clients, so they are hidden. Turn this on only with written permission for each logo; they
  then appear on the About page, labelled as Hirayama Holdings' clients.
- `SITE['social']`: add real profile URLs to show social links; nothing is shown until you do.
- `LEGAL_UPDATED`: the "Last updated" date on the Terms and Privacy pages. Change it whenever the legal text changes.

## Text from the live site

All the text on www.elevatearabia.com is on this site, in all four languages, apart from the
few things listed below. That covers the home page, the eight services with their approach, support areas and outcomes, the sector
pages, the story, mission and six values, the partner's history, the team's roles, and the
legal pages. The last comparison with the live site, page by page and including the text
behind its tabs, was on 10 November 2026.

- `SERVICE_AREAS` in `content.py` holds the eight services as the live site words them. The
  Services page shows each one in full: the approach, the typical support areas, and what the
  service helps to achieve.
- The home page's service list, the Advisory page's three disciplines, and the Automotive
  Industrial Consultancy and Construction Technology pages use the same entries. Their `area=`
  key in `SERVICES` names the entry they use, so each text exists once.

Some things were changed or left out on purpose:

- **"Over 1500 companies found their solutions with us"** is left out. The figure appears to
  be the partner's, not Elevate Arabia's. Add it back only once it is confirmed for Elevate.
- **Social links:** the live site's LinkedIn, Facebook and Instagram icons point to Wix
  template accounts, not to Elevate's profiles. Add the real ones in `SITE['social']`.
- **Terms and Conditions:** six sentences that read as research notes ("Saudi official
  website terms commonly…", "SDAIA states that…", "The PDPL is the principal Saudi law…") are
  left out. Every clause itself is here.
- **Privacy Policy:** the line about cookies is left out, because the site sets no cookies.
- **Format only:** phone numbers are spaced ("+966 53 333 7712"), the address reads "Jeddah,
  Saudi Arabia", and the live site's "01:", "02:" label numbering is replaced by the design's
  own section labels.
- **Corrections:** "Natural Development" now reads "National Development", and spelling
  ("Cearer", "eveyone", "focussing") and grammar in one team role are corrected.

Two claims come from the live site unchanged and should be checked before launch: the
partner's revenue figure (JPY 8.84 billion in Q1 FY2025) and "your project is 40% faster" for
Quadratech.

## Messaging apps (`site.env`)

WhatsApp, WeChat and LINE appear on the Contact page and in the footer, and WhatsApp also
appears on the Contact page's first screen. Their details live in `site.env`, one per line:

| Setting | What to put | What visitors get |
|---|---|---|
| `WHATSAPP_NUMBER` | International number, e.g. `+966533337712` | A WhatsApp chat with a greeting already typed, in the page's language |
| `WECHAT_ID` | The WeChat ID | The ID with a "Copy ID" button (WeChat has no web link that opens a chat) |
| `WECHAT_QR` | Optional: file name of a QR code image in `assets/images/contact/` | The QR code under the ID |
| `LINE_ID` | The LINE Official Account ID, e.g. `@elevatearabia`, or a full `https://line.me/...` link | An "Add us on LINE" link |

- Leave a value empty to hide that app.
- Add `# placeholder` after a value and every build reminds you to replace it.
- A GitHub repository variable with the same name (Settings → Secrets and variables → Actions →
  Variables) overrides the file, so the number can change without editing code.
- The build checks each value and stops with a clear message if one is malformed.

## Deploy to GitHub Pages

1. In the repo, open **Settings → Pages → Build and deployment** and set **Source** to **GitHub Actions** (one time).
2. Merge to `main`. The workflow `.github/workflows/pages.yml` builds the site and publishes it at
   `https://<owner>.github.io/<repo>/`. You can also run it manually from the **Actions** tab.

Pull requests run the build and link checks only, without deploying.

A deploy is live about a minute after the merge (see the **Actions** tab). GitHub Pages lets
browsers keep pages for up to 10 minutes, so reload to see a change straight away. Stylesheet
and script addresses carry a hash of their content (`styles.css?v=…`), so a browser never runs
a new page with the previous deploy's CSS or JavaScript.

The site is **noindex by default**, so a preview deploy never competes with the live site in search.

### Going live on elevatearabia.com

1. Settings → Pages → **Custom domain**: `www.elevatearabia.com`. Add the DNS record GitHub shows you
   (a `CNAME` for `www` pointing to `<owner>.github.io`), then tick **Enforce HTTPS**.
2. Settings → Secrets and variables → Actions → **Variables**: add `INDEXABLE` = `true`.
3. Re-run the workflow. Canonical URLs and `sitemap.xml` pick up the custom domain automatically.

Before switching the domain, work through the sign-off list in [`docs/REVIEW.md` §5](docs/REVIEW.md#5-confirm-before-this-replaces-the-live-domain),
including a lawyer's review of the Terms and Privacy text.

Old Wix addresses (`/home-1`, `/blank`, `/blank-1` … `/blank-5`, `/terms-and-coniditions`,
`/privacy-policy`) redirect to the new pages, so existing links and search results keep working.
GitHub Pages cannot send true 301 redirects; these are instant redirects with a canonical tag.
For real 301s, put a CDN such as Cloudflare in front of Pages and add the same rules there.

## Client logos

Logos are shown as one monochrome set: grey in light mode, inverted in dark mode. Every file
is black ink on a transparent 360×160 canvas, so all logos share one size and visual weight.
To add or replace one, save the original as `<slug>.png` (any size, white or transparent
background) in a folder, then run:

```bash
pip install pillow numpy
```

```bash
python3 scripts/prepare_logos.py path/to/originals assets/images/clients
```

Add `('slug', 'Company name')` to `CLIENTS_NETWORK` in `content.py`, or
`('slug', 'Company name', 'https://example.com/')` to make the logo link to the company's
website (it opens in a new tab). The build checks that every logo is the right size.

## Browser QA (optional)

Checks every page at 8 widths (320–2560px), in light and dark mode, for overflow, JS errors
and WCAG AA text contrast. It also confirms that forced dark mode (the "darken websites"
setting on Android browsers) leaves the page exactly as designed.
It covers all four languages, and also checks that the headline and main button are on the first screen of a 1280×720 laptop,
that 1920px and 2560px screens get larger text, content across most of the width and the intro beside the headline,
that the logo follows the theme, plays its intro on arrival and on the home page but not on other pages, lifts on hover, and stays still with reduced motion,
that the landing animation covers the page on arrival, glides the wordmark into the header, ends within 3.5 seconds, skips on a key press, replays on reload, and never plays between pages or with reduced motion,
that stylesheet and script URLs carry a content hash,
that scrolling reveals every block while nothing on the first screen starts hidden, and that reduced motion or no JavaScript gives a still page,
that the moving logo strip sits under the home page header, pauses with its button and is a still grid with reduced motion,
and tests the mobile menu, anchor offsets under the sticky header, contact form validation, the
mailto output, the old-address redirects, that no cookies are set, that no research notes
remain in the legal text, and the 404 page. On the translated sites it also checks `lang`/`dir`,
untranslated text, the language menu, and the form messages and email in each language.

```bash
npm install --no-save playwright && npx playwright install chromium
```

```bash
python3 build.py && node scripts/qa.cjs --shots
```

Screenshots are written to `qa-output/`, which git ignores.

## Design

Palette from the website review: mostly white and sand, navy for the footer and one highlight
panel per page, and one red as an accent only. A matching dark theme follows the visitor's
system setting. Every colour is a token in `styles.css` with a light and a dark value, and
`color-scheme: light dark` stops browsers from repainting the page with their own dark mode.

| Token | Value | Use |
|---|---|---|
| `--ink` | `#0f2137` | Navy: headings, footer, call-to-action panel |
| `--text` | `#1c2430` | Charcoal body copy |
| `--muted` | `#55606d` | Secondary copy (6.4:1 on white, 5.7:1 on sand) |
| `--tone` | `#7a8793` | Second tone in large headlines only |
| `--soft` | `#f6f2ea` | Warm sand panels |
| `--accent` | `#c00000` | The one red: buttons, numbering, small markers. Never a background. |
| `--line` | `#e6e2da` | Hairline dividers |

- **Type:** IBM Plex Sans for English and Readex Pro for Arabic (400/500/600, self-hosted in
  `assets/fonts/`, SIL Open Font License), with one type scale on every page. Readex Pro was
  chosen from eight Arabic typefaces (see `docs/ui-audit.md`) and loads only where Arabic text appears.
- **Logo:** one vector file, `assets/images/brand/elevate-wordmark.svg`, traced from the original
  7167px artwork. The header inlines it, so it is sharp at any size and its letters follow the
  theme: navy on the white header (beige on white is only 2.4:1, so confirm the navy with the
  brand owner) and the original beige in dark mode.
  - **Landing animation:** when a visitor arrives from another site or types the address, a
    navy curtain fills the screen and the wordmark forms on it in its original colours. The
    seven letters fade up one after another, the red line (the logo's own "elevate" stroke)
    draws up out of the V, the 改善 (kaizen) mark appears, and the tagline rises in underneath.
    A red hairline then draws across the foot of the screen, and the curtain lifts, the page
    "elevating" into view, while the wordmark glides up into its place in the header and takes
    the header's colour. The page header rises in behind it.
    - It lasts about 2.4 seconds, and any click, tap, key or scroll skips it.
    - It plays on arrival from another site, from a typed address or bookmark, and on every
      reload. To replay it while presenting, reload the page.
    - It never plays with reduced motion switched on in the visitor's system settings, or
      without JavaScript. The CSS ends it on its own, so the page is never left covered even if
      `app.js` fails to load.
    - The code is the "landing animation" parts of `styles.css` and `app.js`.

    If it never plays on your own computer, reduced motion is probably on. Check:
    - **Windows:** Settings → Accessibility → Visual effects → Animation effects.
    - **macOS:** System Settings → Accessibility → Display → Reduce motion.
    - **iPhone and iPad:** Settings → Accessibility → Motion → Reduce Motion.
    - **Android:** Settings → Accessibility → Remove animations.

    Remote desktop sessions often turn animations off as well.
  - **Home page intro:** back on the home page from inside the site, the header logo plays the
    same letter-by-letter intro on its own (about 1.6 seconds). Other pages inside the site play
    neither. Both read only the referrer, and store nothing on the visitor's device.
  - **On hover or keyboard focus:** the red line lifts gently along its own angle.
  - **Limits:** motion that starts on its own ends within 2.5 seconds, as WCAG 2.2.2 requires, so
    the logo never loops at the edge of the visitor's view. With reduced motion, the logo stays
    still.

  The footer, which is always dark, shows a beige copy that the build writes to `dist/`. To
  change the logo, edit the SVG in a vector editor. Keep the seven letter paths (one per letter,
  in order) inside `<g id="logo-letters">`, the id `logo-kanji`, the red bar as one `<line>`, and
  `color="#0f2137"` on the root.
- **Home page photo:** the Jeddah waterfront and its new towers at dusk fill the end side of the
  home page header, as an image of the city's development. A small caption on it names the
  place. The lit spire on the far horizon is very likely the Jeddah Tower under construction.
  The caption does not name it, because the photo's own description does not.
  - **History:** it replaced a night view of King Fahd's Fountain (not recognisably Jeddah),
    then a photo of Nasseef House in the old town; the owner asked for modern development and
    technology instead.
  - **How it was chosen:** a panel of three judges chose it from about 260 freely licensed
    photos of the waterfront and new skyline, the Haramain railway stations, the airport, the
    Jeddah Tower and KAUST, scoring each for city identity, how it crops and how it fits the
    brand. Its blue-hour
    sky matches the navy of the headline and the dark theme.
  - **Source:** a photo by the Saudi Press Agency (SPA), from its Creative Commons portal, licensed
    CC BY-SA 4.0. The caption credits the agency, links to the source and the licence, and says
    the photo is cropped. The cropped files are shared under the same licence (see `CREDITS.md`).
  - **Wide screens (from 1200px):** a panel the full height of the header, running to the edge of
    the screen, beside the headline, intro, buttons and figures. The header then fills the first
    screen (up to 62rem tall). In Arabic the panel is on the left.
  - **Smaller screens:** a band the full width of the screen, above the headline.
  - **Motion:** it opens upwards from its foot as the landing curtain lifts, and settles from a
    slight zoom.
  - **To change it:** set `HERO_PHOTO` in `content.py`. It lists a tall crop (the panel) and a
    wide crop (the band), each in three sizes in `assets/images/brand/`, and the focus point of
    each crop. It also holds the photographer's credit, if the licence asks for one; the credit
    then appears in the caption, linked to the source and the licence. The caption's place name
    is `hero_photo_place` in each language's `UI`. Record the source in
    `assets/images/brand/CREDITS.md`.
- **Motion:** the logo's red line is the motif. Every movement is short and vertical and uses one
  easing curve (`--glide`: a quick start and a long, soft finish).
  - Page headers rise in, one line after another, as the page opens.
  - Blocks below the first screen rise into view as they scroll in, lists item by item.
  - The red dash before each section label draws itself in.
  - The home page figures (8, 7, 26) count up.
  - A thin red line under the header tracks reading progress, in browsers that support
    scroll-driven animations, and the header gains a soft shadow once the page scrolls.
  - Under the pointer, a red line runs along service and sector rows, and client logos lift
    slightly.

  Content is never hidden without JavaScript, and blocks already on screen are never hidden.
  With reduced motion switched on in the visitor's system settings, nothing moves. The code is
  the "motion" part of `styles.css` and of `app.js`.
- **Ideas adapted from deepl.com** (patterns only, not DeepL's branding or assets):
  - **Trust strip.** The client and partner logos sit right under the home page header, in two
    rows that drift slowly in opposite directions and fade out at the edges. They stop under the
    pointer or keyboard focus, and a pause button stops them for good, as WCAG 2.2.2 requires
    for anything that moves for more than 5 seconds. With reduced motion, or without
    JavaScript, the logos are a still grid.
  - **Soft light behind page headers.** A faint sand glow, with a trace of the brand red, in
    the top corner. It is navy in dark mode and mirrored in Arabic.
  - **Tinted band.** "How we work" on the home page sits on a full-width sand band, which breaks
    up the run of white sections.
  - **A letter in each language of the site** on the closing call to action: E, ع, 中 and あ,
    one for each of English, Arabic, Chinese and Japanese. They rise into place as the panel
    scrolls into view. They are decorative, hidden from screen readers, and shown only on
    screens 1000px wide or more.
- **Scale:** every size is in `rem`, and the root text size grows with the screen: 16px up to
  1280px wide, 18px at 1920px, 20px at 2560px, and at most 22px. Type, spacing, icons, logos and
  the content width all grow together, so a large monitor shows the same composition at a
  readable size instead of a small column in a sea of white. The scale starts from the
  visitor's own browser text size, so a larger default text setting makes the whole site larger.
- **Layout:** 76rem max width (1216px on a laptop, about 1520px on a 2560px screen) and
  two-column sections (heading on the start side, content on the end side), stacking to one
  column below 900px. On wide screens the section heading stays in view while its content
  scrolls past. From 1100px wide, page headers put the intro beside the headline, and from
  1200px the home page's header fills the first screen, with the Jeddah photo running to the
  screen edge beside it.
  The team list fills four columns.

## Contact form

The form validates in the browser, then opens a pre-filled email to `SITE.enquiry_email` in the
visitor's mail app. Nothing is sent to or stored by the website, which keeps it fully static.
To accept submissions directly, point the form at a form backend and update the Privacy Policy.
The site sets no cookies and has no analytics, so it needs no cookie notice. If you add analytics,
add a consent notice and update the Privacy Policy first.
